      Mini C reference

      Mini C is a teaching subset of C: char short int long float double, arrays and strings.

      Declare and assign

      #define SIZE 5        // a named constant
const int LIMIT = 100;
int x, total = 10 + 2 * 3;
int marks[SIZE] = {70, 85};
x = total % 4;
x++;  x--;  x += 2;  x *= 3;   // also -= /= %=
if (!x) print(0);              // ! is "not"

      Print

      #include <stdio.h>   // optional, keeps it real C
printf("Total: %d\n", x);
printf("%d %d\n", a, b);
print(x);      // short form: x and a new line

      printf supports text, %d, %%, \n and \t.

      Read input

      int n;
printf("Enter n: ");
scanf("%d", &n);          // type it in the Input box
scanf("%d %d", &a, &b);  // two at once

      Decide

      if (x >= 2 && x != 5) {
    x = x - 1;
} else {
    x = 0;
}

      Repeat

      while (x < 10) { x++; }
for (int i = 0; i < 5; i++) {
    if (i == 1) continue;   // skip to the next turn
    if (i == 3) break;      // leave the loop
}
do { x--; } while (x > 0);  // runs at least once

      Choose

      switch (day) {
    case 1: printf("Mon\n"); break;
    case 6: case 7: printf("Weekend\n"); break;
    default: printf("Other\n");
}

      Functions

      int square(int v) {
    return v * v;
}
void show(int v) { print(v); }

show(square(4));   // call them

      Finish

      return x;      // main's value becomes the exit code

      Not available

      Pointers, struct, unsigned, ?:, bitwise operators, goto, #if, macros with parameters, x++ inside a bigger expression.

      Every feature in three steps. In each AI feature the model only suggests; the compiler checks before you see it.
      

      Start here
      The three things to try first.
      1. Open hello.c in Workspace and press Run (F5). The program is compiled, built and run; its output appears in the Terminal.
      2. Open broken.c. The red squiggles and the Problems tab show every mistake at once, with a plain-English explanation.
      3. Click Test the referee in the AI panel to watch the compiler reject wrong answers. It works even without Ollama.
      

      Compile and the pipeline track
      Checks your program as you type.
      1. Type in the editor: the program is compiled half a second after you stop.
      2. The track above the code has a lamp per stage (Lex, Parse, Semantic, IR, Build, Run). Violet = passed, red = stopped here.
      3. Hover a squiggle for the explanation; click a lamp to see what that stage produced.
      

      Run, with input
      Builds a real program and runs it.
      1. If the program uses scanf, type the numbers in the Input box above the Terminal, separated by spaces (e.g. 3 10 20 30).
      2. Press Run (F5), or Enter in the Input box.
      3. The Terminal shows the build command, the output and the exit code. Tick -O2 to build with gcc's optimisations.
      

      Types, arrays and strings
      char, short, int, long, float, double, arrays and text.
      1. Arrays: int marks[5] = {70, 85}; (indexes 0 to 4), 2-D: int m[3][3];, as a parameter: int sum(int a[], int n).
      2. Strings are char arrays: char name[20] = "Ann"; with strlen strcpy strcat strcmp, %s in printf/scanf, characters like 'A' with %c.
      3. Every array access is checked when the program runs: going past the end, a string without '\0' or copying too much stops with a clear message instead of a crash.
      

      C features: loops, switch, ++ and #define
      Write it the way you would in real C.
      1. Open c_features.c and press Run: it uses ++, +=, !, break, continue, do ... while, switch, int a, b;, const and #define.
      2. Mistakes C itself allows are flagged as warnings: a stray ; after while (...), a case with no break, x < 0 && x > 100, a loop counter changed inside the loop, a constant calculation that overflows.
      3. Open bug_20 ... bug_24 and click Find bugs: running the program confirms most of them (a loop that never ends, the case that fell through, the overflowed value).
      Checked by the compiler: thousands of random programs give the same output as gcc (python tools/fuzz.py).
      

      Debug
      Run the program one line at a time.
      1. Click in the margin left of a line number to set a breakpoint (red dot).
      2. Press Debug (F9). Use Step over (F10), Step into (F11), Step out, Back and Continue (F8).
      3. The Variables tab shows the call stack, every variable and the output so far.
      

      Parser choice and Parse trace
      See the lex & yacc parser work.
      1. Set the Parser chip (top bar) to Lex & Yacc (LALR).
      2. Open the Parse trace tab: every shift and reduce step, with the stack and the next token.
      3. The badges say whether the hand-written parser built the same tree. Check with flex & bison runs real yacc if it is installed.
      

      Look inside the compiler
      One tab per compiler stage.
      1. Tokens: what the lexer read. AST: the syntax tree.
      2. IR: the three-address code; hover a line to highlight its source. Control flow: blocks, loops and back edges.
      3. Call graph: who calls whom, recursion. Target code: the generated C and the assembly.
      

      AI: Fix errors
      For code that does not compile.
      1. Click Fix errors. The model gets your code plus every error the compiler found.
      2. Watch the card: each attempt is shown, then checked.
      3. Click Review and apply to see the change side by side, then Apply to file.
      Checked by the compiler: the fix must compile, keep all your functions and at least 60% of your code.
      

      AI: Optimise
      For code that compiles.
      1. Click Optimise. The model gets your code and facts the compiler proved (e.g. 2 * 3 is always 6).
      2. Each suggestion says what changes and why it is faster.
      3. Review the side-by-side change and apply it if you like it.
      Checked by the compiler: the new program is run on the VM and must print and return exactly the same.
      

      AI: Document
      Beginner comments for any code, even broken code.
      1. Click Document. For broken code, each error gets an // ERROR: comment; for fixed code, // FIXED:.
      2. Turn on Document automatically to do this after every compile (slower on a laptop).
      3. Review and apply, or open it as a new file.
      Checked by the compiler: the code itself must be identical, token for token: only comments may be added.
      

      AI: Find bugs
      Finds mistakes that compile but go wrong.
      1. Click Find bugs. Within a second the compiler's findings appear: rules suspect problems (including array and string mistakes such as i <= 5 on a 5-element array, strcpy into a too-small array or == on strings) and the program is run to confirm them (confirmed by running). Try the bug_*.c files in Workspace.
      2. The model then adds a short verdict and explanation for each one, with the changed line(s) as the fix.
      3. Want the whole corrected program? Click Propose a full fix (slower). Works without Ollama too (rules + run only).
      Checked by the compiler: the proposed fix must compile and run without the error.
      

      AI: Refactor
      Cleaner code with the same behaviour.
      1. Click Refactor. The compiler finds patterns such as a counting while loop that should be a for loop.
      2. Each change has a Review this change button.
      3. The model only writes the explanations; the compiler makes the changes.
      Checked by the compiler: the refactored program must print and return the same.
      

      AI: Explain flow
      Loops, calls and how fast the program is.
      1. Click Explain flow. The compiler finds loops, recursion and a Big-O estimate.
      2. The model explains them and may suggest a faster algorithm.
      3. A faster version shows its VM step count against the original.
      Checked by the compiler: the faster version must behave exactly like the original.
      

      Test the referee
      Proof that the compiler checks the AI.
      1. Open any program and click Test the referee.
      2. Wrong answers are built from your code (a changed number, an off-by-one loop, a deleted line…) and judged: red = rejected.
      3. Click Try to fool it yourself, edit the right-hand side, choose the feature and Submit to the referee.
      Checked by the compiler: the same checks as every real AI answer.
      

      If the AI is slow
      Local models run on your own computer.
      1. Each card shows live progress: thinking, writing (characters so far), checking. Asking the same question again is instant.
      2. Untick Document automatically so only the buttons you click ask the model.
      3. Pick a smaller model in the model chip (e.g. qwen2.5-coder:3b), or run ollama ps to check it is on the GPU.
